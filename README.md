# ACR-PINN

Official implementation accompanying the manuscript:

**Architecture--Optimization Co-Design for Physics-Informed Neural Networks via Layer-wise Coordinate Adaptation and Gradient Conflict Resolution**

ACR-PINN combines two complementary components for physics-informed neural
networks (PINNs):

- **Layer-wise Dynamic Adaptation (LDA)** constructs layer-specific coordinate
  representations and combines two encoding branches through input-conditioned,
  feature-wise gating.
- **Gradient-Conflict-Resolved PINN (GCR-PINN)** applies the established PCGrad
  projection rule to the PDE residual, initial-condition, and boundary-condition
  losses before gradient aggregation.

The repository provides the benchmark implementations, frozen configurations,
analysis utilities, and tests used for the revised study. Generated training
outputs and model checkpoints are intentionally excluded.

## Repository structure

- `common/`: shared architectures, optimization methods, diagnostics,
  scheduling, and reproducibility utilities.
- `burgers/`, `helmholtz/`, `klein_gordon/`, `lid_driven_cavity/`,
  `poisson_5d/`, and `schrodinger/`: one training entry point per benchmark.
- `configs/`: experiment configurations and launch manifests.
- `experiments/`: consistently named launch, audit, analysis, and plotting
  utilities; see its local README for the file groups.
- `data/`: reference data required by the benchmark implementations.
- `tests/`: protocol, architecture, optimizer, and reproducibility tests.

See [`docs/experiments.md`](docs/experiments.md) for the mapping between the
manuscript analyses, configurations, and post-processing utilities.

## Installation

Python 3.10 is recommended. Create an isolated environment and install the
dependencies from the repository root:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

The formal CUDA experiments used Python 3.10.20, PyTorch 2.0.1+cu117,
CUDA 11.7, NumPy 1.26.4, SciPy 1.15.3, and Matplotlib 3.10.8. The code also
selects MPS or CPU when CUDA is unavailable.

## Quick validation

Run the test suite before launching an experiment:

```bash
python -m pytest -q
```

Inspect a single configured condition without starting training:

```bash
python experiments/run_experiment.py \
  --config configs/burgers.json \
  --problem burgers \
  --architecture lda \
  --optimizer pcgrad \
  --dry-run
```

Inspect a frozen experiment matrix:

```bash
python experiments/run_manifest.py \
  --manifest configs/lda_ablation_manifest.json
```

Manifest validation is the default behavior. Add `--execute` only after checking
the selected configuration, output location, and accelerator; the formal
experiments are computationally expensive.

## Evaluation protocol

The four core conditions are Std-PINN, GCR-PINN, LDA-PINN, and ACR-PINN. Core
experiments use master seeds 19018--19022 with matched initialization, sampling,
and gradient-order seed bundles. Collocation points are regenerated by
deterministic randomized Latin-hypercube sampling at every iteration. Evaluation
uses the prescribed final iteration and points excluded from training and model
selection.

The representative-baseline comparison is intentionally separate and uses fixed
collocation sets because RBA-PINN and BRDR-PINN retain pointwise residual
histories associated with persistent training locations.

Training outputs are written to `results_*` directories, which are ignored by
Git. Reference inputs under `data/` remain version controlled.
